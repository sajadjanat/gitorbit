# GitOrbit 0.5.4

Recover from rejected pushes in the app. Before sending commits, GitOrbit checks the actual push destination for changes that are missing from your local preview. A stale remote or non-fast-forward rejection opens **Sync before pushing** with incoming commit counts and a reviewable list.

Choose **Fetch and check**, then **Pull incoming commits** when your branch is only behind or **Merge incoming commits** when both sides have new commits. Sync uses the reviewed commit, preserves existing commit IDs, and refuses to proceed with uncommitted file changes or an existing Git operation. Changing the branch or remote after review requires a new check. A fresh push preview is required before you explicitly push the result.

If a merge conflicts, open **Version Control** to review, resolve, stage, and commit it. **Abort merge** restores the pre-merge branch after a warning that edits made to resolve conflicts will be discarded. Other Git operations and mismatched fetch/push destinations show guidance. Fetch authentication failures offer cancellable Git Credential Manager sign-in and an explicit fetch retry.

The recovery controls are available in English, Persian, Arabic, and Simplified Chinese with RTL/LTR layouts. The four README translations include the new workflow.

The application identity, Windows upgrade code, and updater signing key are unchanged. Existing GitOrbit and updater-enabled Workspace Monitor installations can update in place with saved workspaces preserved.
