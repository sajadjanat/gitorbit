# GitOrbit 0.5.5

Create a local branch directly from repository details. Choose **Create branch**, enter a name, and GitOrbit creates the branch from the current HEAD and switches to it, preserving staged, unstaged, and untracked changes. Invalid names, duplicate branches, repositories without an initial commit, and unresolved conflicts show guidance. Detached HEAD can be saved to a new branch.

Branch creation refuses to proceed during an unfinished merge, rebase, cherry-pick, or revert, including after conflicts have been resolved and staged. This preserves the operation metadata and merge parents. Linked Git worktrees are supported.

After branch creation, Version Control refreshes files, upstream, and diffs while preserving the commit-message draft. Push previews and Git history refresh for the new branch. **Commit and Push** stays disabled while details reload and when the new local branch has no upstream.

The form and operation guidance support English, Persian, Arabic, and Simplified Chinese with RTL/LTR layouts. Duplicate submissions are blocked, and failed operations can be retried without losing the branch name. The duplicate translation entry that prevented production builds has been removed.

Thanks to @mohammad-h-sb1 for the branch-creation contribution in [PR #1](https://github.com/sajadjanat/gitorbit/pull/1).

The application identity, Windows upgrade code, and updater signing key are unchanged. Existing GitOrbit and updater-enabled Workspace Monitor installations can update in place with saved workspaces preserved.
