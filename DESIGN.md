# GitOrbit

Use actual shadcn/ui components, React, Radix, and Tailwind tokens. Support light, dark, and system modes; Neutral, Violet, Ocean, and Forest palettes; a saved custom accent. Apply theme tokens at the document root so dialogs share the theme. Geist text, Geist Mono for counts and paths, and Lucide icons. Support English, Persian, Arabic and Chinese; use logical spacing and RTL/LTR direction, while preserving LTR paths, hashes and code.

The primary view is a compact table: repository with branch below, unique changed files, commits to push, commits to pull, next action, and an actions menu. Show all repositories by default; attention filtering is explicit. Workspace tabs show labeled attention counts. Changes are amber, push/pull blue, failures red, and clean status muted green. Labels always accompany color. Zero is explicit; missing upstream is labeled and unavailable/stale counts are suppressed. Clicking a repository opens Version Control first, with Git graph last. Keep commit rows compact with continuous colored parent connections, merge nodes, refs, author, and date.

Each workspace continues monitoring while its tab is inactive. Local file notifications trigger debounced scans; periodic scans recover missed events. Remote fetch is explicit or opt-in every 60 seconds. Display scan and fetch timestamps separately. Unknown upstream and failed scans must never appear clean.

Keyboard navigation uses Radix tabs, native buttons, accessible names, focus rings, and searchable repositories. Closing a tab removes monitoring only. Version Control groups staged, changed, and unversioned files with selection checkboxes and a diff pane. Stage or unstage only selected paths; commit the existing index with an explicit message. Pull one repository or all in the active workspace with fast-forward only, preserving local changes and reporting each result. Writes are explicit; never push automatically.

Context menus are anchored to the clicked item and share actions with visible menu buttons where appropriate. Right-clicking an unchecked file targets that file; right-clicking a checked file targets its checked group. Rollback, reset, unshelve and deletion require review. Shelf snapshots are named, local to a repository and separate from Git stash; previews expose working, staged and unversioned content before restoration.

Branches opens with the current branch selected. Show only local and remote branches in its list, with the current branch first and remote branches collapsed until requested or matched by search. Selecting a row inspects it; switching branches always requires an explicit checkout review. The selected branch exposes checkout, compare and merge where applicable, with rename, rebase, upstream and deletion in More actions. Use short hashes with the full hash available on hover.

Repository tools is one menu for Shelf, Stashes, Tags, Remotes, Submodules, and Recovery and history. These tools replace the secondary seven-tab strip; each tool provides a clear return to Branches. Tags and recovery references belong in their own tools, not the branch list. Preserve reviewed local tag deletion and creating a branch from a tag there. In Version Control, keep stage/unstage, opening Shelf and refresh visible; selected shelving, rollback, ignore, patches and stash live under More file actions or the file context menu.

File lists use local SVG file-type logos, including compound filenames such as Blade templates; type colors are independent of Git status labels. Media diffs show the actual before/after snapshots with shared image zoom and a checkerboard for transparency. Added/deleted media shows only its existing side. PDF pages render locally with page navigation; audio/video requires explicit playback. Unsupported or oversized media shows type, size, and a short explanation. Support the same preview in changes, outgoing/history commits, file history, stash/shelf and revision browsing. See `docs/file-previews.md` for formats and limits.
